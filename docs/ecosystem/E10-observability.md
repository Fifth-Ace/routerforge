# E10 — Storage Doctor and Network Doctor (F11/F12 scoped candidate)

Base: bcdafee24d87dfdcda282a663ca45de59edd8bbd (E09 accepted). Development-only; no new dependencies or services.

## F11 Storage Doctor

The existing 60-second Storage Doctor snapshot loop and manual SMART interface remain in charge. Add kernel diskstats deltas (512-byte sectors, bytes/s, operations/s, completed-I/O mean latency and busy-time percentage). No new scheduler, disk commands, SMART invocation or self-test. First sample, reset/wrap, missing counters, elapsed interval outside 1–300 seconds and ambiguous disk identities produce unknown rather than fabricated zero. Require a non-duplicated reported hardware ID and same device path; recheck reported identity after reading counters. Hardware IDs can still be nonunique or reused and removal between observations can be missed. No rates or continuity for volatile IDs. Limit eight disks, four mounted partitions per disk, 96 points per mount (15-minute cadence, up to 24 hours). Clear absent or changed identities and changed filesystem size. A linear estimate from net free-space decline requires at least four points and a 30-minute span, capped at 365 days; it is not a prediction of workload or drive lifetime. Capacity points and new I/O baselines are volatile. Existing persistent error and temperature history is not replaced. Mount identity uses device/mount/size, not guaranteed filesystem UUID. Existing storage collection and SMART policy are unchanged; no new wake commands. Existing kernel incident detection is not a complete USB audit trail.

## F12 Network Doctor

Reuse existing Route Inspector, Flow Explorer, common policy picker and DNS/TCP/HTTP/ICMP checks. Add explicit TLS (also selectable in Doctor; off in preset profiles), verified with system roots, requested hostname/IP SAN, TLS 1.2 minimum; no verification bypass, HTTP request, alternate port, or redirect within TLS probe. Connect time includes DNS resolution and TCP establishment, TLS handshake measured separately. Five-second total TLS deadline, at most two simultaneous TLS calls. Distinguish TCP-stage, TLS-stage, certificate, timeout and busy results; the prior DNS/TCP error classes are preserved. ICMP variation is the ping tool's mdev/stddev, not a universal jitter metric; absent loss/RTT remains unknown. No combining TCP/HTTP duration with ICMP RTT. Reject HEAD for active `/probe` and `/doctor`; GET remains the explicit existing API. Existing HTTP redirect semantics, route verdict heuristics, flow attribution and address selection are unchanged.

Keep 64 most recent manually requested probe results (including selected checks inside Doctor, excluding internal gateway/Internet checks) in the existing process, no automatic probes or persistence. New read-only `/v1/probe-history` returns local target, kind, port, timing and bounded outcome; raw output/error text and resolved address arrays removed. Local history does contain target hostnames/IPs, visible to the same existing module API audience. UI loads it on demand; existing per-window history and clear action are unchanged. It is not a multi-location measurement or proof of censorship/outage. No new flow payload capture.

Support Bundle V2 receives only optional validated counts of retained manual probe outcomes and tracked disk/counter baselines via existing health requests. No disk identity, mount paths, target, timing, raw error, or additional probe is included in these counts. Counters reflect retained observations, not a health verdict or lifetime statistics.

Tests: storage parsing/delta/identity/reset/capacity and TLS local certificate + busy gate; native history/HTTP and Support Bundle projection tests included for full CI. No hardware validation. Persistent new sample history, normalized Foundation event producers, end-to-end device/flow attribution refinements, storage UUID and external recovery integration are open. Existing root/LAN access policy remains. No changes to security modules, package lifecycle, router configuration or publication.
