# DNS Router Lite P19 — DEV

Лёгкий самостоятельный DNS-контроллер на AdGuard DNSProxy v0.86.0. Общий DNS
используется для остальных доменов; списки exact/suffix направляются к назначенным
UDP/TCP/DoT/DoH/DoQ upstream. Сохранены явный fallback, локальные зоны, кэш,
журнал последних 128 запросов, атрибуция upstream, health/RTT/p95. Блокировщика
рекламы и DHCP нет. Транспорт определяется настройкой, а не ID upstream.

## Настройка

1. Выбери DNS по умолчанию, добавь нужные DNS и привяжи списки доменов.
2. «Сохранить и запустить DNS» применяет сохранённую конфигурацию.
3. «Проверить готовность», затем «Включить для LAN» явно включают перехват
   обычного UDP/TCP 53 для br0. Системный DNS Keenetic остаётся включённым.
4. Проверь запросы реального устройства в журнале. Внутренние readiness-пробы
   не попадают в клиентские счётчики, журнал, health и p95.

Назначенный клиенту адрес DNS не определяет upstream после перехвата. DoH/DoT/
DoQ приложений, DNS внутри VPN, OUTPUT роутера, mDNS и другие порты сюда не входят.
Начальная поддерживаемая область — один проверенный br0 с неперекрывающимися
LAN-префиксами. Неоднозначная топология отклоняется. IPv4-only br0 допустим;
если br0 имеет IPv6, обязательны отдельные IPv6 listener и ip6tables.

«Вернуть штатный DNS» сохраняет Gate OFF и снимает собственный перехват; далее
действуют обычные правила роутера, включая правила других установленных модулей.
«Остановить DNS» сохраняет service OFF + Gate OFF, снимает собственные правила
и клиентский профиль, затем останавливает listener. Ошибка безопасного снятия
оставляет управление и listener доступными для восстановления.

## Состояние и восстановление

Независимый `config.json.intent.json` хранит service_enabled,
interception_enabled и applied_revision. Снимки последнего Apply лежат в
`config.json.applied/<sha256>.json`; файл service-active.json — совместимое
зеркало для отката, а не источник нового намерения. Запись: временный файл 0600,
fsync, rename, fsync каталога. Повреждённое/неизвестное/симлинк-состояние не
считается разрешением запуска. Черновик никогда не применяется при восстановлении.

Свежая установка: оба OFF. Reboot, restart и новые обновления сохраняют ON/OFF.
Maintenance временно снимает перехват и listener, сохраняя намерение и снимок.
Go supervisor перезапускает аварийно завершившийся дочерний процесс (до 5 раз
за минуту); отдельная проверка восстанавливает упавший listener из применённого
снимка (до 3 попыток). Остановка при уже мёртвом daemon использует --offline-stop с обеими process
locks: OFF не теряется, чужой живой процесс не затрагивается. После исчерпания
бюджета нужно устранить причину и явно
повторить действие. Старый socket удаляется только при доказанном мёртвом
владельце и совпадении PID/start/dev/inode/ctime; чужие файлы не удаляются.

Gate показывает desired и observed отдельно: ACTIVE, DEGRADED, CONFLICT,
RECOVERY_REQUIRED. ACTIVE означает последнюю успешную проверку правил,
очерёдности, lease и собственного DNS-ответа; verified_at указывает её время.
Это не доказательство прохождения пакета конкретного LAN-клиента. Истёкший lease
не отображается ACTIVE. Ошибка конфликтующего AWGM DNS не исправляется изменением
чужого компонента: нужен выбор совместимой конфигурации и явный повтор проверки.

## Netfilter и ограничения

Собственные объекты: NAT RF_DNS_LITE_GATE, hash:net RF_DNS_LITE4/6, tag
RF-DNS-LITE:P19 и два ограниченных br0/lease INPUT ACCEPT на высокий порт в каждой
семье. Штатные _NDM_* и чужие цепочки не очищаются. Собственный PREROUTING jump
проверяется перед штатным перенаправлением; multicast/broadcast исключены.
После firewall reload свой netfilter.d/40-routerforge-dns-controller.sh только
ставит событие в очередь через Go Unix-клиент. При OFF он ничего не включает.

Heartbeat 4 секунды, lease 60 секунд. Xtables: совместимость -w 1 / -w / старый
вариант без -w, ограниченные по времени процессы и до трёх повторов только для
реальной блокировки. Длительная блокировка приводит к ошибке состояния, а не
ложному ACTIVE. Повторные перестановки ограничены бюджетом, бесконечной борьбы
за позицию с другим модулем нет.

Ядро должно предоставлять NETLINK_NETFILTER/conntrack dump и точечный DELETE.
Предварительная проверка отклоняет недоступный backend, неоднозначные зоны и
опасные link-local потоки. Никакие Python/socat/conntrack-CLI не требуются.
На переключении удаляются только точно идентифицированные управляемые DNS
кортежи с CTA_ID; глобального conntrack flush нет. На отключении/падении удаляются
только высокопортовые перенаправления RouterForge. Это необходимо: NAT применяется
к первому пакету соединения, истечение ipset само по себе не стирает conntrack.

Supervisor покрывает падение DNS-процесса, пока сам продолжает работать. При гибели
всего Entware, supervisor или зависании ядра мгновенный автоматический возврат
уже существующих NAT-сессий не гарантирован; lease ограничивает новые совпадения.
Независимого от Entware watchdog здесь нет. Реальная совместимость netlink ABI,
NDM/AWGM, IPv6 REDIRECT и аварийного fallback требует аппаратного испытания.

## Первый переход с r1267 и откат

Старый prerm r1267 вызывает пользовательский Stop и удаляет service-active.json.
Новый prerm не может изменить уже исполняющийся старый скрипт. Поэтому перед
первым opkg install нужно извлечь НОВЫЙ бинарник из проверенного IPK и выполнить:

```sh
/path/to/new/routerforge-dns-router --config /opt/etc/routerforge/dns-router/config.json --prepare-upgrade
```

Используется Go Unix-клиент, не curl. На время передачи состояния прекрати изменения
через старый UI. Резервная копия всей директории конфигурации и проверенный r1267
IPK должны быть сохранены до обновления. Препроверка требует отключённого старого
индивидуального клиентского профиля и совпадения live applied_revision со снимком.
DNS ON сохраняется. RECOVERY_REQUIRED/осиротевшие NAT-правила не доказывают Gate
consent: Gate будет OFF, пока пользователь явно его не включит. Только live ACTIVE
с подтверждённым снимком переносится как Gate ON и проходит новый preflight.

После сохранения намерения старую службу останавливает штатный старый prerm;
после установки новый init восстанавливает применённый снимок. Первый handoff
не является атомарной транзакцией со старым UI: не меняй его состояние параллельно.
Preparer также проверяет точную форму старого неподписанного Gate и сохраняет
одноразовый cleanup-план. Новый Resume снимает только доказанные старые правила
и их DNS conntrack-кортежи до восстановления DNS; чужое содержимое вызывает
CONFLICT. После перехода проверь TCP/UDP с реального клиента.

Для отката: новым бинарником выполни `--service-control maintenance`, сохрани его
для `--restore-upgrade-snapshot`, установи проверенный старый IPK. Его postinst
может запустить management с OFF после нового prerm remove; останови старый init
через stop, новым сохранённым бинарником выполни
`--config /opt/etc/routerforge/dns-router/config.json --restore-upgrade-snapshot`,
затем запусти старый init. Старый DNS прочитает совместимое зеркало последнего
применённого снимка. Старый Gate заново разрешается вручную: r1267 не поддерживает
новый persistent Gate intent. Не подменяй снимок текущим черновиком.

## Проверка без curl

```sh
/opt/bin/routerforge-dns-router --service-status
/opt/bin/routerforge-dns-router --verify-dns 192.168.10.1:55358
```

Core browser proxy также поддерживается. Диагностика сервиса проверяет заданный
вход и выборочные основные upstream, а не весь LAN и не доступность всех доменов.

## Разработка и критерии

Go 1.26.8, отдельный go.mod, build tag dns_router_lite, DNSProxy v0.86.0 сохранён.
Кэш 0–8 МиБ, до 32 обработчиков; DNS-журнал только в памяти. GOMEMLIMIT=48MiB —
мягкая цель GC, а не верхняя граница RSS. Второй Go-процесс supervisor не содержит
DNS engine; фактический расход двух процессов нужно измерить на роутере.

```sh
cd modules/dns-router-lite
go test -tags dns_router_lite ./...
go test -tags dns_router_lite -race ./...
go vet -tags dns_router_lite ./...
```

Тесты разделяют реальные локальные DNS endpoints, stateful симуляцию netfilter/
conntrack, переходы package/reboot и реальные Unix socket/process lifecycle.
Последние требуют Linux AF_UNIX и RF_DNS_LITE_TEST_BINARY; CI собирает host binary
и считает отсутствие предпосылок ошибкой. Локальная среда с запретом AF_UNIX
помечается BLOCKED. Hardware E2E всегда PENDING до явного испытания на Keenetic.
AWG использован как архитектурная справка (MIT); исходники реализованы независимо.
