# E06.1 — Recovery Center / F06 local candidate

Adds an Admin Recovery tab over the existing Config Vault and legacy maintenance archive inventory. No new store, no new service, no export of object bytes. New explicit snapshots record the Admin build version; old manifests remain readable and report unknown version. Manifest-to-manifest comparison covers path, digest and mode; selected artifact verification reads and validates its object then compares bounded current bytes. Legacy archives are displayed via the existing endpoint and retain their existing behavior.

Explicit new captures use NoPrune; a conservative capacity check refuses capture before evicting any prior snapshot. Existing capture callers keep existing retention behavior. The reserve is one manifest limit (1 MiB), plus artifact bytes (even if deduplicated). Failed captures can leave unreferenced content-addressed objects, as with existing capture failures. Admin's existing mutation lock serializes operations in this process, not other writers.

Selective restore is deliberately limited to one existing `logging.json` with 0600 mode and validated standard Entware logging settings in both preimage and snapshot. No custom log location or RAM mode, no missing-file creation, no unrelated deletion, no security configs, service intent, arbitrary paths, Observer/catalogue/binding state or protected module adapters. Exact plan token binds manifest ID, selected artifact ID/path and current/target SHA/mode. Apply rechecks after a single-file NoPrune safety capture and atomically writes the saved file through existing safety helper, then verifies readback. No service activation. Rollback is a fresh preview/confirmation of the safety snapshot; on uncertainty, no blind retry or overwrite. Audit records metadata in Admin logs and safety snapshot reason. Legacy full restore is unchanged and retains its existing semantics; do not use it as the new selective restore.

Open F06 work: module-native DNS/NFQWS backup adapters, USB/SMB selection, module-specific version compatibility, persistent operation history beyond the existing snapshots/log, broader safe restore, hardware acceptance. Existing archive backup contents can include sensitive data at rest; no new secret export. No change to three maintenance-only modules or public releases.
