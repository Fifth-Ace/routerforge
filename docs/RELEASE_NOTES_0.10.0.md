# RouterForge 0.10.0

Есть вещи, которые в сетевом софте почему-то принято считать нормальными.

Например: чтобы открыть один сайт, человек должен узнать, что такое NFQUEUE, fake, split, disorder, hostlist, SNI, ClientHello, conntrack и ещё десяток терминов, о существовании которых он вчера прекрасно не подозревал. А если после четырёх часов правки конфигов всё заработало — система объявляется «гибкой».

**RouterForge 0.10.0 — наша попытка немного прекратить этот цирк.**

Это большой Stable-релиз после `0.9.1`: новый NFQWS Manager, интеграции DPI Detector и NFQWS Menu, расширенные Network Tools, нормальный менеджер процессов, усиленные Backup/Restore и recovery-механизмы, плюс заметное снижение фоновой нагрузки.

Функций стало больше. Роутер при этом работает меньше. Оказывается, программа не обязана постоянно использовать CPU только ради того, чтобы доказать, что она занята.

## Новый модуль: NFQWS Manager

В RouterForge появился **седьмой полноценный компонент — NFQWS Manager**.

Он работает с существующим `nfqws2-keenetic` и объединяет в одном интерфейсе конфигурацию и профили, сохранённые конфиги, полный `nfqws2.conf`, пользовательские списки, библиотеку и базу стратегий, импорт, диагностику, автоподбор, песочницу, историю, логи, резервные копии, runtime health, скрипты и системную информацию.

Shell никуда не исчез. Просто теперь он снова инструмент для случаев, когда он нужен, а не обязательная форма приветствия.

## Автонастройка и AutoSelect

Указываете проблемный сайт — RouterForge сначала проверяет, есть ли вообще проблема, которую должен исправлять NFQWS, а затем может собрать кандидатов из production-профилей, встроенного пула и пользовательской библиотеки.

Кандидаты проверяются через изолированные NFQUEUE. Во время работы показывается живой прогресс. Если рабочих вариантов несколько, RouterForge показывает их все и отдельно отмечает рекомендацию.

Рекомендация — это рекомендация. Если программа показывает одну кнопку со словами «мы всё решили за вас», это уже не помощник, а маленький цифровой чиновник.

## Нашёл — ещё не значит применил

Успешный запрос не получает автоматического права переписать рабочую конфигурацию.

Перед Apply RouterForge повторно проверяет выбранную стратегию, проверяет ожидаемый SHA active config, строит preview, создаёт backup, применяет изменение и проверяет итоговое состояние. При проблеме предусмотрен rollback.

Новый результат добавляется отдельным профилем. Существующие `NFQWS_ARGS_CUSTOM` не заменяются.

Очень сложная инженерная идея: если пользователь уже что-то настроил, не надо молча это уничтожать.

## Стратегии и импорт

Можно хранить собственные стратегии, проверять их в песочнице и импортировать команды или `.bat` / `.txt`.

RouterForge разбирает вход, показывает преобразования и позволяет сохранить пригодные профили без изменения production.

Случайный файл из интернета всё ещё не считается достаточным основанием для немедленных root-мутаций. Возможно, однажды эта мысль доберётся и до остальной индустрии.

## ClientHello

Инструменты ClientHello получили законченный рабочий сценарий: образец можно получить с устройства и использовать при диагностике и подборе обхода.

Это полезно там, где приблизительного «браузер вроде делает примерно так» уже недостаточно. Сеть вообще становится приятнее, когда вместо «примерно» появляются измерения.

## NFQWS Menu

NFQWS Manager интегрирует **[rndnaame/nfqws-menu](https://github.com/rndnaame/nfqws-menu)** как upstream-источник готовых стратегий, списков и blobs.

Источник показывается явно. RouterForge не переименовывает чужую работу в «нашу уникальную Enterprise AI Cyber Platform» только потому, что так красивее звучит на слайде.

## DPI Detector

В NFQWS Manager встроена полноценная интеграция **[Runnin4ik/dpi-detector](https://github.com/Runnin4ik/dpi-detector)**.

RouterForge находит установленный `dpi-detector`, проверяет совместимость binary с текущим rootfs, определяет версию, позволяет открыть оригинальный консольный интерфейс, а для DPI Detector v5 предоставляет графический режим RouterForge для machine-readable tests.

Если уже работает NFQWS, VPN, proxy или другой bypass, RouterForge прямо предупреждает, что результат описывает **текущий сетевой путь**, а не мистическую «чистую правду провайдера».

Диагностика, которая честно говорит об ограничениях, менее эффектна. Зато значительно полезнее.

## Network Tools

Network Tools теперь содержит четыре законченных пользовательских пространства: **Сетевой доктор**, **Маршруты**, **Потоки** и **Активные проверки**.

Можно смотреть reachability, RTT и loss, выполнять traceroute, разбирать route decision ядра, смотреть conntrack/flows и запускать ограниченные probes без изменения конфигурации.

Последний этап сетевой диагностики — «какого хрена?» — мы пока не победили. Но количество шагов до него уменьшили.

## Monitoring

Monitoring получил менеджер процессов с CPU, RSS, PID, PPID, пользователем, состоянием, количеством потоков, именем/командой, поиском и сортировкой.

Теперь при загрузке процессора можно перейти от научного метода «ну, наверное, опять сеть» к более конкретному «вот эта зараза жрёт 73% CPU».

## Admin / Control

Admin расширен: Service Inspector, File Manager, Terminal, Backup / Restore, diagnostic snapshots, Support & Recovery и watchdogs.

Внутри всё больше опасных операций используют общие transaction, atomic-write и rollback primitives.

Потому что успешный exit code ещё не означает, что система осталась в состоянии, которое вы вообще собирались получить. Большая часть истории системного администрирования состоит из вещей, которые выглядят очевидными сразу после аварии.

## Меньше фоновой нагрузки

В `0.10.0` RouterForge стал значительно меньше опрашивать систему просто потому, что где-то существует таймер.

Monitoring собирает тяжёлые данные по необходимости. DNS экономнее обращается с историей и фоновыми проверками. Уменьшена лишняя работа с temperature/storage/services.

На **Keenetic Hopper KN-3811** в проверенном idle-сценарии четыре основных процесса RouterForge вместе использовали в среднем **меньше 1% CPU**. Core, DNS и Monitoring в сопоставимом замере использовали примерно **на 20% меньше памяти**.

Это не обещание одинаковых цифр на каждом роутере. Это измеренный результат на конкретном железе — потому что цифры без контекста обычно называются рекламой.

## DNS

DNS получил оптимизации CPU/RAM и усиленные mutation/recovery paths.

Также внутри создан большой фундамент будущего DNS policy routing: inventory политик Keenetic, evaluator правил, persistent store, dry-run, transaction/rollback и аппаратно проверенные recovery primitives.

**Отдельного пользовательского DNS Policy Router в 0.10.0 нет.**

Нет вкладки. Нет публичной кнопки активации. Мы не выдаём фундамент за готовый дом только потому, что бетон уже дорогой.

## MIPS / MIPSel

Пакеты выпускаются для `aarch64-3.10`, `mips-3.4` и `mipsel-3.4`.

Отдельное ручное подтверждение experimental-mode для MIPS/MIPSel убрано. Runtime compatibility checks и предупреждения о малой RAM, одном ядре CPU или отсутствии swap остаются.

Убрали бюрократию. Не тормоза.

## Что не обещаем

Раздел GeoSite / GeoIP в NFQWS Manager всё ещё помечен **«В разработке»**.

Пользовательского DNS Policy Router пока нет.

Эти вещи не попадают в список готовых возможностей `0.10.0`.

Удивительно, но функция не становится законченной оттого, что её название уже хорошо смотрится в release notes.

## Итог

Предыдущий Stable: `0.9.1`.

Release train: `0.10.0-beta.1` → `0.10.0-beta.5`.

Новый Stable: **`0.10.0`**.

Главная идея релиза довольно простая: автоматизировать то, что машина делает лучше человека; показывать, что реально произошло; перед опасным изменением делать backup; после изменения проверять результат; если проверка не прошла — уметь вернуться назад; и не выдавать недописанную функцию за революцию только потому, что для неё уже придумали красивое название.

Удивительно, сколько программного обеспечения можно улучшить, если начать с этих пунктов.
