# DNS Router Lite — DEV

Самостоятельный DNS-сервис RouterForge на транспортном ядре AdGuard DNSProxy
v0.86.0. Поддерживает доменные списки, точные/суффиксные правила, явный DNS по
умолчанию, настроенный резерв, UDP/TCP/DoT/DoH/DoQ, ограниченный кэш и 128 последних
запросов в памяти. Нет блокировщика рекламы, DHCP-сервера, облачной статистики или
перехвата чужого DNS.

## Установка и включение

Устанавливается только DEV IPK `routerforge-dns-router` для aarch64-3.10. Исходники
RouterForge Core и его установленная версия не меняются. При свежей установке
запускается только управление; клиентский DNS Keenetic не изменяется.

1. Открой модуль DNS Router и обнови страницу с очисткой браузерного кэша.
2. В блоке «DNS-сервис · DEV» выбери DNS по умолчанию. Для DSTest адрес сервиса:
   `192.168.10.1:55358`, сети: `127.0.0.0/8,192.168.10.0/24`, кэш: 1 МиБ.
3. Привяжи списки к собственным DNS и нажми «Применить DNS». Все сохранённые
   доменные правила и default начнут обслуживаться одним listener.
4. «Проверить сервис UDP/TCP» отправляет уникальные DNS-вопросы и проверяет
   фактически выбранный основной upstream. Это проверка прямого входа сервиса,
   а не доказательство подключения клиента через Keenetic.
5. В раскрывающемся блоке подключения укажи MAC одного зарегистрированного
   тестового устройства и нажми «Подключить устройство». Модуль создаст профиль
   `RF_DNS_LITE`, сохранит прежнее назначение и проверит конфигурацию после записи.
   Транзитный DNS-перехват и общий DNS engine не переключаются.
6. Отключи собственный DoH/Private DNS на тестовом устройстве, оставь DNS-адресом
   роутер. Сделай новые запросы и смотри журнал модуля. Это аппаратная проверка
   реального клиентского пути; заранее она не объявляется пройденной.

Флажок сохранения в Keenetic отдельно разрешает `system configuration save`:
сохраняется вся текущая конфигурация роутера. Без флажка профиль действует только
в текущей running-config и может исчезнуть после перезагрузки.

## Отключение и повторный запуск

«Вернуть прежний DNS устройства» снимает только собственный профиль и возвращает
предыдущее назначение. Перед изменениями сверяется сохранённое владение. При
сторонних изменениях DNS откат останавливается с объяснением вместо перезаписи
чужих настроек.

«Остановить DNS» сначала снимает собственное подключение устройства, затем
останавливает listener и выключает его автозапуск. Остановка пакета выполняет ту
же операцию до завершения процесса. Не удаляй пакет с обходом prerm, пока на него
назначен клиент.

Обычный запуск демона восстанавливает только последний явно применённый снимок
из `config.json.service-active.json`. Сохранённый, но не применённый черновик не
включается после перезапуска. При неудачном Apply выполняется попытка вернуть
предыдущий работающий DNS и сообщается её результат. При ошибке чтения снимка
управление остаётся доступным.

Если профиль сохранён в Keenetic, а Entware/сам сервис недоступен, назначенное
устройство может остаться без DNS. Открой Keenetic по IP и верни этому устройству
профиль System или его прежний профиль. Независимого от Entware аварийного
watchdog в этой DEV-сборке нет. Первое испытание предназначено для одного клиента.

## Переход с native/P10

Новый режим не использует регистрацию отдельных доменных зон. Активный ownership
старого P10 необходимо сначала отключить старой версией; новый сервис откажется
стартовать поверх него.

Существующие правила сохраняются. По явному Apply использованные native-селекторы
с однозначным URL DoH импортируются в прямые DoH-настройки. URL/SNI и список
сохраняются, IP разрешается перед подключением. Неоднозначные старые DoT/native
записи не угадываются: добавь прямой DoT/DoH-сервер с известными настройками и
переназначь список. В рабочем пути локальные порты stubby не используются.

Локальные имена и обратные зоны передаются сохранённому штатному DNS на
127.0.0.1:53. Публичный default никогда не направляется обратно в тот же сервис.
Встроенный DNS Keenetic остаётся включённым; порт 53 не занимается.

## Проверка и границы

В сетевых тестах используются реальные локальные UDP/TCP/DoT/DoH endpoints.
Проверяются 171 независимая зона, default, служебные имена, exact-исключения,
кэш, запрет утечки отрицательных ответов к резерву, восстановление после ошибки
применения и отказов команд профиля. Native ndmc в этих тестах — модель,
соответствие конкретной KeeneticOS требует испытания на устройстве.

Новый модуль и зависимости изолированы отдельным go.mod; сборка Go 1.26.8.
Legacy shadow QUIC исключён build-tag `dns_router_lite`. Корневой go.mod и
экспериментальные сборки остаются на прежней цепочке. Полные лицензии реально
скомпилированных модулей включаются в DEV IPK.

Кэш: 0–8 МиБ; по умолчанию в UI 1 МиБ. Сетевых обработчиков: до 32 одновременно.
Лог DNS не записывается на диск и не отправляется наружу. GOMEMLIMIT по умолчанию
48 МиБ — мягкая цель GC, не обещание верхнего предела RSS. Утверждение «легче
AdGuard Home» требует сравнительных замеров на одном роутере.

Проверка из SSH без curl:

```sh
/opt/bin/routerforge-dns-router --service-status
/opt/bin/routerforge-dns-router --verify-dns 192.168.10.1:55358
```

Последняя команда подтверждает только заданный вход и выборочные основные
upstream. Успех настроенного fallback не выдаётся за доказательство доступности
назначенного основного сервера.

## P15 — системный DNS Gate (DEV)

Опциональный режим перехвата UDP/TCP 53 для LAN br0 через временные IPv4/IPv6 ipset hash:net timeout.
Требует доступных ipset, iptables, ip6tables, IPv6 listener, dual-stack br0 и отдельного подтверждения в интерфейсе.
Никакие штатные DNS-профили Keenetic и цепочки _NDM_* не изменяются. Включение не переживает
перезагрузку и не выполняется при установке/обновлении. Lease 15 секунд продлевается каждые 4 секунды
только пока работает процесс RouterForge. Если процесс исчезнет, NAT-правила станут неактивными
после истечения lease; старые conntrack-сессии могут доживать отдельно.

Первое включение допустимо только на DSTest под наблюдением; E2E IPv6/IPv4, тест планшета,
падение DNS Lite и firewall reload должны быть проверены на аппаратуре до общего релиза.
