Состояние

Быстрая проверка runtime и safety boundary
Настройка nfqws2 сверху вниз
Обычный режим показывает только основные вещи. Экспертный — базовые и служебные детали.
Подписи блоков — локальные метаданные RouterForge: помогают назвать секции «YouTube», «Игры», «Рабочий VPN» и т.п., но не меняют синтаксис nfqws2 и не попадают в конфиг.
01
Интернет-интерфейс
ISP_INTERFACE
Куда уходит интернет-трафик. Обычно eth3 / eth2.2 / ppp0. Можно указать несколько интерфейсов через пробел.
Интерфейс провайдераМенять только если точно знаешь WAN-интерфейс.
02
Базовая загрузка nfqws2
NFQWS_BASE_ARGS
Lua-модули и blobs, которые подгружаются один раз при запуске и используются стратегиями ниже.
В этом блоке upstream запрещает --new. Профили здесь не переставляем и не дробим.
03
HTTPS / TCP
NFQWS_ARGS
Главная стратегия для HTTPS/TCP. Применяется к доменам в зависимости от выбранного режима работы.
Порядок внутри этого блока сохраняем как в исходном конфиге. --new здесь не допускается самим nfqws2-keenetic.
04
QUIC
NFQWS_ARGS_QUIC
Отдельная стратегия для QUIC, обычно UDP/443. При запуске nfqws2 к ней автоматически добавляются режим доменов и IPSET.
05
Прочий UDP
NFQWS_ARGS_UDP
WireGuard, STUN, Discord, MTProto и другие UDP-протоколы. Этот блок не использует NFQWS_EXTRA_ARGS.
Это отдельный UDP-профиль: доменные MODE_LIST / MODE_AUTO / MODE_ALL на него не навешиваются.
06
Режим обработки доменов
MODE_LIST / MODE_ALL / MODE_AUTO → NFQWS_EXTRA_ARGS
Сами MODE_* — служебные шаблоны upstream. Мы их не редактируем, только выбираем один из них.
Это именно NFQWS_EXTRA_ARGS. Upstream помечает MODE_LIST / MODE_ALL / MODE_AUTO как «don't change» — поэтому они здесь только как понятный переключатель.
07
IP-списки
NFQWS_ARGS_IPSET
IP/CIDR, которые обрабатываются независимо от доменного режима. Обычно это ipset.list и ipset_exclude.list.
08
Дополнительные стратегии
NFQWS_ARGS_CUSTOM
Единственное место, где upstream разрешает несколько профилей через --new. Только здесь можно менять блоки местами.
Порядок блоков влияет на итоговую строку запуска. Перемещение ↑ / ↓ доступно только здесь — остальные секции следуют исходной архитектуре nfqws2.
09
IPv6
IPV6_ENABLED
Включает аналогичные правила обработки для IPv6.
10
TCP-порты
TCP_PORTS
Какие TCP-порты iptables отправляет в NFQUEUE. Пустое значение отключает обработку TCP.
11
UDP-порты
UDP_PORTS
Какие UDP-порты попадают в NFQUEUE. Убери 443, если QUIC обрабатывать не нужно.
12
Политика Keenetic
POLICY_NAME / POLICY_EXCLUDE
Позволяет ограничить обработку устройствами из политики Keenetic или, наоборот, исключить их.
Имя политикиТочное имя политики Keenetic.
13
Логирование
LOG_LEVEL / LOG_DEBUG_PATH
Debug-лог нужен только для диагностики. Постоянно держать его включённым обычно не требуется.
Файл debug-логаПуть используется при LOG_LEVEL=1.
14
Служебные параметры
NFQUEUE_NUM / USER / CONFIG_VERSION
Показываем для понимания механизма, но в обычном интерфейсе не даём случайно ломать.
