# RouterForge: учёт установок и техническая телеметрия

RouterForge Core может передавать на отдельный сервер проекта две категории сообщений:

1. Базовый учёт: случайный 128-битный идентификатор установки, факт первой регистрации, периодическое подтверждение активности. Он работает независимо от переключателя технической диагностики. Это помогает оценивать популярность проекта, но не гарантирует, что все устройства онлайн. Никакого отслеживания удаления нет.
2. Техническая диагностика: **включена по умолчанию**, доступна для отключения в «Настройки → Статистика RouterForge». Отправляет только версию Core, семейство архитектуры, грубые диапазоны нагрузки CPU и RAM, температуру и код общего состояния. После отключения новые диагностические сообщения не создаются; локальная статистика продолжает работать.

Не передаются DNS-запросы, посещённые домены, SNI, IP или MAC-адреса как поля сообщений, ключи, подписки, SSID, серийные номера или логи. Сервер при соединении всё же обрабатывает исходящий сетевой IP; поэтому считать механизм полностью анонимным нельзя.

Запросы отправляются только через HTTPS с проверкой сертификата. Ожидаемая периодичность подтверждения активности — около суток. Установка и запуск RouterForge не зависят от доступности сервера сбора. Начиная с этапа T4 в `dev`, Core использует проверенный сервер RouterForge: `https://telemetry.fifthace.ru/v1/events`. Сайт статистики обслуживается отдельным Collector; никаких данных в GitHub, Forgejo, Synology или сторонние аналитические сервисы Core не отправляет. Первое событие отправляется асинхронно после запуска Core, а не из установочного `postinst`. Опубликованная Beta 9 этим изменением не затрагивается.

Постоянный случайный ID не помещается в переносимые резервные копии при условии, что резервная копия создаётся штатным механизмом, исключающим внутренний файл состояния. Любое стороннее копирование всего `/opt/etc/routerforge` может скопировать ID; поддержка безопасного backup/restore — отдельный acceptance gate до массового выпуска.

Подробности схемы и серверной архитектуры: `services/telemetry-collector/README.md`.
