# E07 — Support Bundle v2 / F07 scoped candidate

Replaces the old whole-struct export with explicit allowlisted diagnostic projections. The existing Admin maintenance dashboard and legacy ZIP inventory remain. New archive creation requires an authorized POST preview followed by explicit `SUPPORT_BUNDLE` confirmation and the exact one-use preview token. Old callers without a token receive `SUPPORT_PREVIEW_REQUIRED`; there is no unsafe legacy generation fallback. Existing v1 ZIP files are preserved and labeled unverified in the new UI. The inventory's previous blanket `redacted: true` promise is removed. Legacy downloads require user review in the UI; they are not retroactively sanitized.

## Collection

Five selectable sections: system, packages, modules, foundation, logs. Module health selection covers Admin, DNS, Monitoring, Network Tools, NFQWS Manager and DNS Router. Only fixed Unix socket GET endpoints are used. The three maintenance-only security modules are listed by installed package version only; their runtime APIs are not queried. No arbitrary command, URL, network connection, path, or user-supplied payload is exported. The system section contains architecture, recognized KN model code when available, numeric kernel version, uptime/load/memory/swap and `/opt` and `/tmp` storage measurements without mount sources. Unknown values are null/unknown. Package versions are constrained to known RouterForge patterns. Logs contain numeric counts only from up to 64 KiB of one local RouterForge log, not raw text. Counts are heuristic, not forensic severity or proof of root cause.

Core attaches a bounded numeric summary of normalized in-memory events and CPU sampling to the authorized preview request via a server-owned header (incoming copies stripped). Admin independently reads bounded saved Foundation catalogue/binding metadata and exports counts only, not content, IDs, revisions/hashes or credentials. A missing saved file is reported separately from unavailable. Samples are not an atomic cross-process snapshot; no live binding or routing proof is implied. Core observation unavailable/old Core is reported as partial. No new public Core endpoint.

## Preview and integrity

Single isolated child process, 18-second parent timeout, sequential 1.5-second module requests, fixed input/read limits and capped worker stdout. If a kernel I/O call cannot be cancelled, the worker slot remains occupied until the child exits; no unbounded worker spawning. This limit applies to the new collection, not every pre-existing Admin endpoint (legacy storage dashboard still probes mounts). A timed-out whole collection fails without publishing. Available individual sources produce ok/partial/skipped states. No external storage traversal. The archive is prepared in memory, at most 512 KiB, 64 KiB per entry. Manifest records source state/reason, size and SHA256, selection and privacy exclusions; exact manifest and payload bytes are verified before exclusive publication. Preview is global, one pending archive, expires after two minutes, invalidated by a new preview. Preview token is consumed before write; no blind retry after uncertainty.

ZIPs stay in the existing private `/tmp/routerforge-support` directory (0600 files). Up to eight archives, no silent eviction; explicit exact-name delete is available. Stage and exclusive hard-link publish, fsync and SHA readback; unsupported filesystem semantics fail closed. Existing archives remain volatile. No upload or external sharing. The UI provides local download and legacy warnings. Preview exposes file metadata, not the complete contents; users should review downloaded archives before sharing. This is data minimization, not a guarantee of perfect anonymization. Runtime acceptance, mixed-version UI, and target filesystem behavior remain open until Wave II hardware acceptance. No new package/dependency or protected module source changes.
