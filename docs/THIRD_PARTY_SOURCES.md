# Политика сторонних источников RouterForge

**Черновик архитектуры:** R2
**Дата:** 12 сентября 2026 г.

## Цель

RouterForge App Center поддерживает два пользовательских сценария:

1. Добавление **репозитория приложений** — URL на RouterForge-compatible registry/index, содержащий несколько приложений.
2. Добавление **одного приложения** — ссылка на GitHub-репозиторий либо прямой URL RouterForge-compatible manifest.

RouterForge не должен угадывать команды установки по README и не должен автоматически запускать произвольный код только потому, что пользователь вставил ссылку.

## Источники

### Официальный источник

Встроенный источник RouterForge. Его идентификатор и ключ подписи закреплены в Core. Пользователь не может подменить официальный namespace сторонним источником.

### Сторонний репозиторий

Пользователь вводит HTTPS URL на `index.json`. RouterForge:

- нормализует URL;
- выполняет защищённую загрузку с ограничением размера и времени;
- проверяет schema;
- проверяет registry ID и namespace;
- проверяет подпись, если она заявлена;
- показывает preview;
- только после подтверждения сохраняет источник.

### Отдельное приложение

Для GitHub URL вида:

`https://github.com/OWNER/REPO`

RouterForge ищет только заранее определённые manifest paths:

- `.routerforge/manifest.json`
- `routerforge.json`

Если manifest отсутствует, приложение не считается совместимым с App Center. README не анализируется для автоматического получения install commands.

Разрешается также прямой HTTPS URL на manifest.

## Trust model

Предлагаемые состояния:

- `OFFICIAL` — встроенный источник RouterForge с закреплённым ключом.
- `VERIFIED` — подпись корректна, ключ находится в локальном trust store пользователя.
- `SIGNED UNKNOWN` — подпись корректна, но ключ ещё не принят пользователем.
- `UNSIGNED` — подпись отсутствует.
- `CHANGED` — ранее доверенный ключ или fingerprint изменился.
- `INVALID SIGNATURE` — заявленная подпись не прошла проверку.
- `BLOCKED` — источник или приложение заблокировано.
- `DEPRECATED` — источник помечен как устаревший.

`INVALID SIGNATURE` и нарушение обязательных security invariants должны блокировать установку независимо от global unsafe toggle.

## Подписи

Для первой версии достаточно Ed25519 из стандартной библиотеки Go.

Рекомендуемый формат для Registry:

- `index.json`
- `index.json.sig`
- `key_id` и сведения об издателе в index.

Подпись вычисляется над точными байтами `index.json`.

Для отдельного приложения используется аналогичная пара:

- `manifest.json`
- `manifest.json.sig`

Официальный публичный ключ RouterForge закрепляется в Core.

Пользовательские доверенные ключи сохраняются локально.

## Global risk gate

По умолчанию:

`Разрешить установку из непроверенных источников = OFF`

При нажатии показывается красный confirmation modal.

Пример текста:

> **ВНИМАНИЕ: выполнение стороннего кода**
>
> Непроверенные приложения могут получить права, достаточные для изменения конфигурации роутера, сетевого трафика, файлов и служб Entware. RouterForge не проверяет исходный код каждого неподписанного приложения и не может гарантировать его безопасность.
>
> Включайте этот режим только если доверяете источнику и понимаете план установки.
>
> Это разрешение не отключает проверки целостности RouterForge. Некорректная подпись, попытка подмены официального namespace и заведомо небезопасный manifest будут по-прежнему блокироваться.

Подтверждение:

`[ ] Я прочитал предупреждение и принимаю риски установки стороннего кода.`

Дополнительно пользователь должен нажать красную кнопку:

`РАЗРЕШИТЬ УСТАНОВКУ`

Настройка сохраняется локально. Пока она включена, в App Center постоянно отображается небольшая красная/янтарная плашка:

`Установка из непроверенных источников разрешена`

Каждая установка `UNSIGNED`, `SIGNED UNKNOWN` или иного неподтверждённого приложения всё равно требует отдельного confirmation с показом источника и install plan.

## Install plan preview

Перед установкой стороннего приложения RouterForge показывает:

- источник;
- publisher;
- trust state;
- manifest fingerprint;
- версию;
- URL файлов;
- checksum;
- пакеты;
- создаваемые opkg feeds;
- службы;
- заявленные зависимости;
- ожидаемые изменения;
- наличие install/update/remove actions.

Пользователь подтверждает именно этот plan.

Если plan изменился после preview, подтверждение аннулируется и требуется новое.

## Namespace

Внутренний идентификатор приложения:

`registry_id:item_id`

Примеры:

- `routerforge-community:dns`
- `awesome-keenetic:foo-vpn`
- `single-github-owner-repo:foo-vpn`

Сторонние источники не могут занимать зарезервированный namespace RouterForge.

## Обновления

Приложение обновляется только из своего provenance/source, если пользователь явно не выполняет migration на другой источник.

Удаление источника:

- удаляет metadata и cached registry;
- не удаляет уже установленный пакет;
- помечает установленное приложение как `SOURCE MISSING`;
- сохраняет возможность ручного удаления приложения, если lifecycle известен локально.

## Cache

Настройки источников:

`/opt/etc/routerforge/app-sources.json`

Кэш:

`/opt/var/cache/routerforge/registries/<source-id>/`

Используется last-known-good копия. Невалидный новый index никогда не заменяет последнюю валидную копию.

## Network safety

Для remote source рекомендуется:

- HTTPS only;
- ограничение размера ответа;
- timeout;
- ограниченное число redirects;
- повторная проверка адреса после redirect;
- запрет loopback/link-local/metadata endpoints и иных опасных назначений;
- запрет credentials в URL;
- отказ от автоматического исполнения кода на этапе discovery/refresh.

## UI

Основные вкладки App Center:

`Официальные | Интеграции | Entware | Установлено | Обновления`

Кнопка `Источники` находится рядом с поиском/настройками каталога и открывает Source Manager.

Source Manager показывает:

- Official RouterForge source;
- сторонние repositories;
- single-app sources;
- online/cache/error state;
- trust state;
- число приложений;
- last sync;
- Refresh / Disable / Remove.

Под кнопкой `Исходный код` в About/Settings размещается небольшая плашка:

`Пользовательское соглашение · AS IS`

Она открывает локальную страницу/модальное окно с текстом соглашения и датой редакции.
