## Audit against Master Plan v4 F10

- F10.1: P30 already supports request_do and require_ad. The latter checks upstream AD, rejects unsigned answers and is not local chain validation. No new validator, trust anchor management or claim of local secure/insecure/bogus classification. A validator requires a resource/security ADR and acceptance separately.
- F10.2: P31 implements /96 DNS64 synthesis subject to existing DNSSEC constraints. Show declared NAT64 and configured prefix separately; no NAT64 creation and no connectivity assertion. Active DNS64/NAT64 end-to-end verification remains open.
- F10.3: Existing Gate coverage already distinguishes IPv4, routed IPv6 and excluded link-local scope; expose last observation, listener flag, and hardware pending. No Gate, firewall, DHCP, ndnproxy or stubby changes; further IPv6 hardware cases remain open.
- F10.4: Native client policy already chooses device domain, device/group defaults, inherited common rules and explicit service default. Existing policy cache is isolated by route/client identity; P33 has bounded stats. Compare two exact revisions with explicit hypothetical MAC and separately ranked candidates. Winner is taken from the native policy engine; if diagnostic ranking disagrees, fail closed. Strict group chain comes from native resolver. Does not model ACL, local records, packet processing, dynamic health/balancing, actual identity or network success. No changes to hot path, TTL semantics or cache isolation. Saved and applied snapshots are separate observations; no atomic cross-state promise.
- F10.5: Existing lists cap at 64 and shared rules at 10,000; already have explicit auto refresh. Show rule count/limit, per-list metadata (kind, last recorded update, configured interval), and conflicts among same domain/match/priority with different targets. Not a complete shadowing analysis; first ID in collision group does not necessarily win actual DNS query. Rank and conflict output limited to 32 rows each, total count preserved. No list URL fetch or change to refresh worker, storage or limits. Scale benchmarking and source error/refresh history still open.
- F10.6–8: Existing F01/F04 bindings and F06 native saved-policy restore retained. Explicit audit fetches existing binding metadata; list ID association is not content or runtime verification. Links to existing Policy Objects and Admin; no new write API. Support Bundle adds typed saved feature metadata, no configuration contents or identifiers. Existing P34 history and recent traces remain. Upstream/fallback normalized event producers and persistent history remain open.

## Implementation

Lite diagnostics page adds a manual read-only audit request. GET `/v1/service/policy-audit` optionally accepts one domain and one hypothetical canonical MAC. No network requests, apply, cache clear, or automatic probes. One expensive audit at a time; if occupied return 429. Saved configuration must load; active policy is captured under existing manager lock and evaluated through immutable compiled trie. No exposure of upstream URLs/stamps/certificates in new response. Local UI can display domain/IDs and selected upstream address from native decision. Support Bundle never collects that response; its existing `/v1/status` receives only optional saved features. Separate registry read in browser uses existing Core API.
