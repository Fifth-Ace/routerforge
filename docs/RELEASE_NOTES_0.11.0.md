# RouterForge 0.11.0

У программ есть странная традиция: чем проще задача, тем больше способов превратить её в административную процедуру.

Хотите посмотреть, работает ли защита роутера? Отлично. Вот вам SSH, конфиг, несколько списков, ipset, cron, команды управления и небольшая экскурсия в устройство Linux. Потому что, видимо, кнопка со словами «работает» была бы слишком радикальной идеей.

**RouterForge 0.11.0 немного сокращает этот цирк.**

Релиз небольшой и честный: **один новый модуль и один багфикс**. Без списка из сорока пунктов, где двадцать семь означают «мы передвинули строку на три пикселя».

## Новый модуль: Antiscan Manager

В RouterForge появился **Antiscan Manager** — отдельный модуль для тех, кто использует [dimon27254/antiscan](https://github.com/dimon27254/antiscan).

Сам Antiscan остаётся самостоятельным проектом. RouterForge его не присваивает, не переименовывает в «RouterForge Enterprise Threat Defense Ultra», не ставит молча и не решает, что теперь знает вашу сеть лучше вас.

Он просто даёт Antiscan нормальный интерфейс.

Теперь из RouterForge можно посмотреть состояние Antiscan, разобраться, почему адрес оказался заблокирован, работать с настройками и списками, управлять запуском, расписанием и обслуживанием.

То, ради чего раньше приходилось помнить несколько команд и каждый раз думать: «Так, а вот эта сейчас только покажет состояние или ещё пол-роутера перестроит?» — теперь находится в одном месте.

Опасные действия не превращены в весёлую красную кнопку «СДЕЛАТЬ ХОРОШО». Перед изменениями RouterForge проверяет состояние, применяет их контролируемо и проверяет результат.

Потому что root-доступ — это всё-таки не игровой автомат. Не надо дёргать ручку и надеяться на три вишенки.

## Исправлен статус Keenetic Entware Extras / Geo Split

Была ещё одна замечательная ситуация.

**Geo Split работал. RouterForge говорил, что он не работает.**

То есть маршрутизация жива, всё делает своё дело, а панель стоит рядом и уверенно сообщает:

> **OFF**

Очень полезно.

Примерно как лампочка «двигатель отсутствует» в машине, которая в этот момент едет по трассе.

Причина оказалась в том, что Geo Split работает не совсем как обычная постоянно висящая служба. RouterForge смотрел на него слишком прямолинейно и принимал нормальное поведение за остановку.

В `0.11.0` это исправлено.

Теперь RouterForge смотрит на реальные признаки работы Geo Split и **не показывает предупреждение «служба не работает», когда она на самом деле работает**.

Казалось бы, довольно низкая планка для системы мониторинга.

Но вот мы здесь.

## Версии

В этом релизе мы также придерживаемся нормального независимого версионирования компонентов, а не подхода «вышел новый релиз — срочно поменяем цифру вообще везде».

| Компонент | Версия |
| --- | ---: |
| RouterForge Core | **0.10.1** |
| DNS | 0.10.0 |
| Admin / Control | 0.10.0 |
| Monitoring | 0.10.0 |
| Network Tools | 0.10.0 |
| NFQWS Manager | 0.10.0 |
| **Antiscan Manager** | **0.11.0** |
| Profiling | 0.10.0 |

Сам релиз RouterForge — **0.11.0**, потому что появился новый полноценный модуль.

Core получил **0.10.1**, потому что в нём исправлен баг с определением состояния Keenetic Entware Extras / Geo Split.

Остальные компоненты не менялись, поэтому их версии тоже не менялись.

Удивительная концепция: **если программу не меняли, можно не делать вид, что её меняли.**

## Итого

RouterForge 0.11.0 делает две вещи.

**Antiscan теперь можно нормально контролировать из RouterForge.**

И **RouterForge перестал сообщать, что Geo Split умер, пока Geo Split совершенно спокойно работает.**

Не самый длинный список изменений.

Зато в нём нет пунктов вроде «улучшена стабильность стабильности» и «оптимизирована оптимизация».

Иногда хороший релиз — это не сто новых функций.

Иногда это одна новая полезная вещь и одна старая хрень, которая наконец перестала бесить.
