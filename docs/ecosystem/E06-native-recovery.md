# E06.2 — Native recovery and external Config Vault transport (F06)

Extends the accepted E06.1 Recovery Center. All actions are explicit; existing legacy full restore, security modules, service control, stock DNS, Entware and mount configuration are unchanged.

* DNS Router: select an existing snapshot's exact `dns-router/config.json`. Native saved-policy preview uses the same `Compile` and native revision as ConfigStore. It rejects managed ownership, URL/auto lists, changes to listener/service/advanced options, and Admin conservatively blocks any persistent list binding. These new native endpoints are internal to the Admin orchestration (not public module proxy). Apply captures a NoPrune preimage in Config Vault, proves its native revision, rechecks the plan and uses ConfigStore CAS and readback. Saved only, no service action. Restore the safety snapshot through a fresh preview for rollback. Core's binding state and native store are separate processes; no cross-process atomic lock is claimed. Missing target, unsupported schema or large objects fail closed.
* Policy catalogue: verified portable draft from the exact catalogue artifact. Existing Foundation Preview/Save, If-Match, candidate ETag and binding dependency checks remain authoritative. Existing native revision history is the rollback mechanism (bounded four revisions). No restoration of Observer ID, binding registry or security state. No automatic synchronization.
* NFQWS: existing native backup inventory, new guarded list-only preview/save for existing nonprotected `.list` files, excluding `rf-binding-*`, old/opkg variants and missing targets. Verified bounded backup and preimage, native persistent safety copy without pruning, fresh token, atomic file replacement and digest/mode readback. Persistent backup record/prune/delete serialize inside the NFQWS process. Other writers still have their existing semantics; no global CAS or permanent pin of a safety copy. Native config/library/blob/profile restore retains original workflow, including any existing restart semantics. A running NFQWS may read the changed list; runtime is NOT_VERIFIED. No automatic restart or blind retry.
* USB/SMB: enumerate only existing mounts under `/tmp/mnt/<name>` or `/opt/mnt/<name>`, use existing SMB mount assistant separately. No mount/unmount, credentials or auto fallback. Linux mount identity and open descriptor `mnt_id` must match, including target directory/file. If kernel lacks this evidence, the action fails closed. No automatic creation except `routerforge-recovery` on the selected volume during explicit export. File name generated uniquely, exclusive creation, bounded data, fsync, SHA readback. Uncertain writes may leave a partial encrypted file; no automatic removal or retry. Import only verified encrypted file, never direct config activation. Child process handles mount IO, bounded wait, one outstanding worker; if kernel IO cannot be killed, slot stays busy until reaped. No network filesystem call in main Admin handler. Free space read on demand; storage selection is not persisted.
* Encrypted transport: existing local Config Vault manifest and payloads in AES-256-GCM envelope `RFVAULT-ENC-1`, random 96-bit nonce, random 256-bit raw key (64 hex digits), authenticated header. Key generated explicitly in browser, store it separately; no password KDF or password-derived key, no plaintext export. Key travels over the current RouterForge session; use trusted LAN/HTTPS. Import validates component, schema, all paths/IDs/hashes/modes/sizes and capacity, creates new local snapshot (original ID in reason) without deleting old snapshots or restoring working files. Limits follow existing 2 MiB artifact/8 MiB snapshot and 32 MiB/32 snapshot store; envelope capped 14 MiB. Existing prechange retention behavior stays intact. Unreferenced content-addressed objects can remain on failed import as with existing vault failures. Local vault is not encrypted at rest by this change. External archives contain only selected Config Vault snapshot, not separate NFQWS native inventory.
* History: existing Config Vault safety snapshots, Foundation catalogue history and existing Admin/NFQWS logs record operation evidence. No new durable cross-module audit database. Native configurations not supported by the scoped adapters remain inspect-only or available in their original module workflow.

CI candidate only. Hardware acceptance, mounted USB/SMB compatibility (including mount-ID support, timeout and filesystem durability), real saved DNS/NFQWS restoration, network-service effect and resource measurement remain open. No publication, new dependencies, config activation or protected module changes.
