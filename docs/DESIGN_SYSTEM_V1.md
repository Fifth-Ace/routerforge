# RouterForge Design System v1

## Владелец

**Core** является единственным владельцем общих визуальных токенов и базовых компонентов.
Исходник: `components/core/frontend/static/design-system/routerforge-v1.css`.
Версионированный URL: `/design-system/routerforge-v1.css`.

В v1 система **опциональная**. Подключение не меняет глобальные стили Core и не
вмешивается в остальные модули. Любой модуль должен одновременно подключить
стиль и явно установить `.rfds-scope` на контейнер.

## Контракт и компоненты

- Токены `--rfds-*`: цвета, сетка, шрифты, радиусы, отступы, высота контролов.
- `.rfds-card`, `.rfds-toolbar`, `.rfds-button`, `.rfds-button--primary`.
- `.rfds-segmented`, `.rfds-tabs`, `.rfds-field`, `.rfds-form-grid`, `.rfds-hint`.
- Внешние темы передаются Core как `--rf-*`, новые компоненты их наследуют.
- По умолчанию дизайнерский зелёный акцент; он настраиваемый токен.
- Никаких селекторов, меняющих все `body`, `button`, `input`, `.panel` в других модулях.

## Подключение DNS Router (первый потребитель)

```html
<link rel="stylesheet" href="/design-system/routerforge-v1.css">
<main class="page rfds-scope" id="dnsLiteApp">...</main>
```

Модуль хранит только layout-правила конкретных DNS-экранов в `p22-visual.css`.
Базовые компоненты и основные токены приходят из Core. Дополнительные DNS-функции,
API, жизненный цикл и конфигурация **не меняются**.

## Миграция модулей

1. Ввести новые классы и опциональный импорт в одном модуле.
2. Проверить светлую/тёмную тему, RU/EN, узкую ширину, доступность и скриншоты.
3. Проверить отсутствие изменений DOM и поведения остальных модулей.
4. Удалять локальные дубли только после прохождения визуальных и функциональных тестов.
5. Выпустить v2 по отдельному URL при несовместимых визуальных изменениях.

## Граница ABI

Это CSS/HTML контракт, не новый RouterForge Core Module ABI. Не добавляет никаких
прав на изменение Keenetic, Entware, DNS Gate, маршрутов или системных DNS.
