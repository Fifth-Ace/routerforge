# RouterForge Versioning Policy

RouterForge использует `MAJOR.MINOR.PATCH` и независимое версионирование компонентов. До выпуска Core `1.0.0` использовались версии вида `0.MINOR.PATCH`. Начиная с 1.0.0 платформа Core придерживается стабильного контракта.

## PATCH

Совместимые исправления ошибок, улучшения интерфейса, надёжности, производительности, безопасности и небольшие функции без смены архитектурного контракта.

## MINOR

Крупные новые возможности, самостоятельные модули, существенные изменения архитектуры или совместимости.

## MAJOR

Core `1.0.0` фиксирует первый стабильный контракт платформы. Будущие MAJOR-версии применяются при несовместимых изменениях публичных контрактов.

## Версии компонентов

Версия выпуска RouterForge и версии отдельных пакетов могут различаться. Неизменённый компонент не получает новую версию только ради общего номера релиза.

Для предварительных OPKG-пакетов используется суффикс `~`, который сортируется ниже соответствующего стабильного выпуска.

Проверить актуальные версии можно в [GitHub Releases](https://github.com/Fifth-Ace/routerforge/releases) и Центре приложений.

Новый компонент при первом выпуске получает текущую версию Core; далее его версия развивается независимо. min_core_version отражает минимальную совместимую версию Core и не обязана совпадать с версией модуля.

## Политика RouterForge 1.0+

Версия платформы относится к Core и не вызывает массовое повышение версий модулей.
PATCH/MINOR выпускается только при фактических изменениях соответствующего компонента.
Неизменённые модули сохраняют собственные версии.

Публичные GitHub Releases содержат только технические заметки.
В RouterForge Stable техническая сводка и необязательная авторская история
показываются в отдельных вкладках. С версии 1.0.0 авторские истории
включаются только в интерфейс RouterForge и не загружаются в assets
или описание GitHub Releases. Исторические публикации не переписываются.
