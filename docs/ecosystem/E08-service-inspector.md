# E08 / Service Inspector — scoped F08 candidate

Extends the existing Admin service inspector, its process/package/port attribution and selected detail. No new runtime service, scheduler, dependency orchestrator, watchdog or mutation. Existing service actions and their guards are unchanged. All three maintenance-only security modules retain their previous view and receive no new probe, boot logic or dependency observation. Native health uses the E07 fixed Unix socket adapter for Admin, DNS, Monitoring, Network Tools, NFQWS Manager and DNS Router only, with a single in-flight request and bounded timeout. Core and unknown services have no new native probe. A native management reply is not a traffic-path check; target availability and running state are separate where supplied by the adapter.

CPU is an estimate of matched processes as a fraction of aggregate system CPU ticks, using two manual inspector reads, a 1–300s window, PID start identity, monotonic counters, and max 256 extra PID reads. Missing/reused PID, discontinuities, first sample and oversized set produce unknown (null). Attribution remains the original inspector's name/package heuristic, can overlap across services, and is not exact ownership or PSS. Process evidence differentiates observed, D-state, zombie-only, not detected and unknown. No claim that an observed process is healthy. Original resource fields and existing action result are retained.

Boot eligibility is calculated only for exact known packaged rc.func init-script Git blob identities, executable bit and the documented ABI/disabled markers. Changed scripts and DNS Router custom supervisor show unknown. This is not a record of boot success or the DNS runtime's desired intent. Package dependency clauses come from bounded opkg status input; preserve Depends and Pre-Depends, alternatives and constraints. Exact installed names are evidence only (no version solving, Provides resolution or inferred runtime dependency graph). No writes to opkg or init scripts.

History is a filtered read of the existing Core ring (/api/platform/events), exact service ID and admin-service component, up to 20 action events. UI shows time, action and outcome codes only. It is process-scoped and records only observed Admin proxy actions; not complete restart history or a persistent log. Existing Foundation producer is unchanged. The Recovery Center jump selects the first snapshot with an exact matching file path (plus known DNS Router/Core paths) and leaves preview/restore guards intact. Support Bundle jump preselects one supported module, without collecting or saving until the user initiates E07 preview; unsupported services open general diagnostics. No automatic restore, activation, telemetry upload or external storage change.

Open: hardware acceptance and actual boot/health observations; richer module-native boot/intent evidence (including DNS Router), persistent lifecycle observation, full runtime dependency graph and more precise process ownership. Existing generic service action behavior is not tightened in this patch. F09 remains separate.
