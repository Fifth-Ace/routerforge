# Архитектура RouterForge

## Основные компоненты

```text
Browser -> RouterForge Core :2233
           ├── Web UI / REST / SSE
           ├── Authentication / Settings
           ├── App Center / Registry / Lifecycle
           ├── Module API / UI host
           └── Unix-socket proxy
                ├── routerforge-dns
                ├── routerforge-admin
                ├── routerforge-monitoring
                ├── routerforge-network-tools
                ├── routerforge-nfqws-manager
                ├── routerforge-antiscan-manager
                ├── routerforge-port-access-manager
                └── routerforge-crowdsec-manager
```

Core — единственный основной пользовательский HTTP-listener платформы. Модули используют локальные Unix sockets, а пользователь взаимодействует с ними через Core. Опциональный Profiling по умолчанию доступен только на `127.0.0.1:6061`.

## Жизненный цикл модулей

Установленный пакет и готовый к работе процесс — разные состояния. Core проверяет манифесты, установленные пакеты и доступность модуля. Обновления выполняются через соответствующий канал с проверкой доступных артефактов и контрольных сумм.

## Границы ответственности

- **Core:** авторизация, настройки, каталог, маршрутизация запросов к модулям, обновления.
- **DNS:** DNS/DoT/DoH, резолверы, измерения состояния и управление DNS-конфигурацией.
- **Management:** службы, процессы, файловые операции, обслуживание и консоли.
- **Monitoring:** сведения о состоянии и ресурсах устройства.
- **Network Tools:** диагностика маршрутов, потоков и сетевого пути.
- **NFQWS Manager:** управление существующим nfqws2 и изолированная проверка стратегий.
- **Antiscan Manager:** управление установленным Antiscan.
- **Port Access Manager:** управление механизмами контроля доступа к портам.
- **CrowdSec Manager:** управление Firewall Bouncer и диагностика блокировок.

## Безопасность

Операции с изменением состояния используют ограниченные серверные контракты, авторизацию и дополнительные подтверждения там, где это необходимо. Общие механизмы проверки путей, ограничения команд, атомарной записи и отката находятся в `internal/safety`.

Административные терминалы являются отдельными явно ограниченными режимами: Entware shell и Keenetic `ndmc`. Веб-запрос не выбирает произвольный исполняемый файл.

App Center отделяет доверие к метаданным проекта от разрешения выполнять действия установки и удаления. Обнаружение локальных Web UI не предусматривает слепого сканирования LAN.

## Frontend

Svelte/SvelteKit/Vite используются при сборке интерфейса. Node.js на роутере для работы RouterForge не требуется.
