# E02 — Подключение потребителей / Consumer integration

Core serves GET `/api/platform/foundation/consumers?consumer=...` with the current ETag and compatible group metadata. An individual group projection requires the same ETag and `id`; stale requests return 409. The user previews a group, then rechecks its generation before inserting it into a native draft. No new permissions, probes, configuration writes, scheduler, credentials or network changes are initiated by this API. Domain and IP list formats are kept separate. DNS Router and NFQWS append without overwriting existing draft content; NFQWS supports only known domain/IP list names in this block. Network Tools selects one host, never scans CIDRs or starts a probe implicitly. Groups containing wildcard semantics, unresolved external list references, disabled devices or unsupported members are blocked in full. Device groups expose enabled connection hostnames only. This is a snapshot import, not a persistent rule binding. Existing list references and native apply paths remain authoritative.

Monitoring exposes a manually requested local metrics projection with v1 metric validation and process-scoped observer ID; unbound device/connection IDs are null. CPU uses the existing sampler, memory is total minus available, swap is total minus free, /opt storage uses existing platform reader, uptime is nullable. Missing load, rates and other sources remain null. No remote health claims. Existing normalized events remain on the E01 ring and its health producers, no new raw payload or event spool. UI shows catalogue references, not claims about active rule dependencies.

Deferred: persistent shared bindings in module configs, authoritative native list-ref resolution, safe stable observer identity, remote snapshots and Portal/rfs runtime integration. No additional libraries or changes to security modules, KeeneticOS, Entware or services. Hardware and browser-device acceptance remain pending.
