# RouterForge 1.0.0 — первый стабильный релиз платформы

## От набора инструментов к единой системе

RouterForge начинался как способ собрать полезные возможности Keenetic и Entware в одном месте. Постепенно он превратился в модульную платформу, где диагностика, управление службами, работа с DNS, сетевые инструменты и защитные механизмы не живут каждый в своей вкладке, терминале и конфигурационном файле.

Версия **1.0.0** — первый большой единый стабильный релиз платформы и **всех 11 официальных пакетов**. Каждый из них имеет реальную версию `1.0.0` в метаданных OPKG, имени IPK и релизном индексе. Core предоставляет общую основу — интерфейс, авторизацию, Центр приложений, обновления и связь с локальными сервисами.

В этом материале две части. Сначала — **все основные возможности RouterForge 1.0**, чтобы новый пользователь понял, что получает. Затем — **подробно о том, что изменилось со Stable 0.14.0**. Это разные вещи: существовавшие раньше функции представлены в обзоре, но не выданы за новинки.

# Часть I. Что умеет RouterForge 1.0

## 1. RouterForge Core — основа платформы

Core объединяет установленные компоненты в общем веб-интерфейсе, доступном обычно на порту `2233`. Он отвечает за авторизацию, настройки, каталог модулей, обновления и отображение состояния системы. Модули подключаются к Core через локальные Unix sockets: для обычной работы пользователю не нужно открывать отдельные веб-порты каждого сервиса.

**Центр приложений** показывает доступные и установленные компоненты, обновления и сторонние интеграции. При изменении состава пакетов используются предварительные проверки, контроль версии и состояния после операции, а не одно только успешное завершение команды пакетного менеджера.

Интерфейс объединяет темы оформления, навигацию, управление состояниями и многоязычные подписи. Отдельное окно «Что нового» позволяет смотреть историю Stable и Beta, не смешивая версии продукта с техническими записями разработки.

## 2. DNS — контроль штатных резолверов

Основной DNS-модуль помогает управлять существующими DNS-настройками и контролировать качество работы резолверов. Он показывает DNS, DoT и DoH, задержки, ошибки, состояние резервных вариантов и позволяет временно отключать серверы без уничтожения сохранённой конфигурации.

Этот модуль **не заменяется DNS Router**: у них разные задачи, и оба входят в модульную экосистему.

## 3. DNS Router — самостоятельная маршрутизация DNS

DNS Router — отдельный сервис, позволяющий обрабатывать обычные DNS-запросы локальной сети и направлять их к нужным upstream по собственным правилам. Он поддерживает UDP, TCP, DoT, DoH и DoQ, выбор DNS по умолчанию, резервные резолверы и управляемые списки доменов.

К одному upstream можно привязать несколько независимых списков. Можно редактировать существующие DNS-серверы без удаления их идентификаторов и связанных правил. Проверка upstream показывает детали соединения и сертификата TLS; журнал помогает понять, какой сервер был выбран и какой действительно ответил.

Для отдельных устройств доступны собственные группы и правила. Расширенные настройки включают обработку DNS-ответов с несколькими IP-адресами, проверки доступности IP, параметры кэша, локальные DNS-записи и дополнительные защитные ограничения. Управляемый DNS Gate позволяет явно включать перехват обычного UDP/TCP DNS для локальной сети — установка пакета сама его не активирует.

## 4. Admin — обслуживание роутера без постоянного SSH

Admin объединяет процессы и службы Entware, файловый менеджер, операции обслуживания, Entware Terminal и Keenetic NDM Console. Предусмотрены резервное копирование и восстановление конфигурации с контролируемыми действиями.

Отдельное направление — управление **syslog-ng**: источники системных журналов, просмотр, экспорт, раздельная история устройств и хранение записей на USB-накопителе или сетевой папке SMB/NAS. Для сетевого хранилища предусмотрен мастер подключения.

## 5. Monitoring — состояние устройства и накопителей

Monitoring показывает показатели процессора, памяти, температуры, сети и накопителей. **Storage Doctor** дополняет обычную телеметрию проверкой физических USB/HDD/SSD-устройств, историей ошибок USB, I/O и файловой системы, температурой дисков и диагностикой SMART.

SMART запускается по запросу пользователя, а не используется как повод постоянно будить спящие диски. История и настройки диагностики учитывают конкретный накопитель, чтобы замена устройства не превращала старые данные в ложную тревогу.

## 6. Network Tools — сетевой инструментарий

В одном модуле доступны **Network Doctor, Route Inspector, Flow Explorer и Active Probes**. Они помогают разбирать маршрутизацию, соединения, сетевые потоки, доступность ресурсов и путь до нужного адреса. Особенно полезно при нескольких WAN, VPN, маршрутах по политикам и сложной домашней или небольшой офисной сети.

## 7. NFQWS Manager — работа с установленным nfqws2

NFQWS Manager предоставляет интерфейс для существующего `nfqws2-keenetic`: настройки и профили, списки, библиотеки стратегий, диагностику сайтов и DPI, тестовые инструменты, автоподбор, контролируемое применение изменений и резервные копии.

Менеджер не подменяет собой исходный nfqws2 — он помогает настраивать, анализировать и обслуживать установленную систему через единый интерфейс.

## 8. Antiscan Manager — управление установленной защитой

Antiscan Manager отображает состояние и диагностику Antiscan, помогает работать с настройками, списками, ipset, планировщиком и восстановлением. Изменения выполняются через предусмотренные операции модуля, а не через произвольные команды, встроенные в обычные формы.

## 9. Port Access Manager — доступ к сетевым сервисам

Port Access Manager объединяет механизмы Port Knocking и контроля доступа к портам: **knockd**, **fwknopd / SPA**, **iptables recent / odin**. Он позволяет работать с настройками, статусом служб, диагностикой и инженерными инструментами, сохраняя отдельные ограничения на операции, которые действительно меняют конфигурацию доступа.

## 10. CrowdSec Manager — защита через Firewall Bouncer

CrowdSec Manager помогает работать с установленными компонентами CrowdSec: Firewall Bouncer, LAPI, ipset и iptables. В интерфейсе доступны состояния защиты, диагностика, данные о блокировках и признаки деградированного состояния, чтобы отличать установленный пакет от реально работающей защиты.

## 11. Profiling — диагностика производительности

Profiling — дополнительный локальный инструмент для анализа производительности RouterForge. По умолчанию он ограничен loopback-адресом `127.0.0.1:6061` и большинству пользователей не требуется. В общем выпуске его версия также `1.0.0`.

## 12. Экосистема и интеграции

**RouterForge Portal** — отдельное браузерное расширение. На главной странице RouterForge предусмотрена информация о нём и ссылка на установку в браузер. Само расширение не устанавливается в Entware.

В Центре приложений представлены информационные интеграции **opffk** и **qWDTT Server Keenetic**: сведения о совместимости и переходы к их веб-интерфейсам. Наличие карточки не означает автоматическую установку сторонней программы.

**RouterForge Server** — отдельный проект для Linux/VPS. Версия RouterForge 1.0 показывает объявление о проекте, информационную карточку со статусом **«В разработке»** и страницу будущей интеграции. Привязка серверов, удалённое управление и обмен через агент/API пока не реализованы — карточка не является устанавливаемым двенадцатым модулем.

## 13. Техническая основа

RouterForge использует Go для серверной части и Svelte 5 для пользовательского интерфейса. Node.js нужен для сборки, но не для работы интерфейса на роутере. Разделение Core и модулей позволяет устанавливать только необходимые компоненты.

Выпуски собираются для `aarch64-3.10`, `mips-3.4` и `mipsel-3.4`. Основная аппаратно проверенная архитектура — ARM64; для MIPS/MIPSEL степень физической проверки зависит от модели и окружения. Пакеты поставляются с индексами и контрольными суммами.

Безопасность строится вокруг ограниченных API, авторизации, предварительных проверок, явного подтверждения опасных действий, атомарного сохранения данных и откатов там, где они предусмотрены конкретным модулем.

# Часть II. Что изменилось после Stable 0.14.0

Этот раздел охватывает изменения из серии **0.15.0 Beta 1–6**, последующие доработки DEV и общую миграцию интерфейсов. Он не пересказывает каждую внутреннюю правку или тестовый коммит, а перечисляет подтверждённые пользовательские функции и исправления по компонентам.

## 1. RouterForge Core и Центр приложений

### Новые функции

- Переработана история обновлений: Stable и Beta представлены отдельно, историю можно просматривать из интерфейса и открывать до установки соответствующего выпуска.
- Добавлено обнаружение новых опубликованных патчноутов и ненавязчивая подсветка непрочитанного выпуска.
- После чтения запоминается версия просмотренного патчноута; при ошибке сохранения браузер сообщает о проблеме.
- Выбор истории учитывает выбранный в Центре приложений канал, а ручное переключение разделов остаётся доступным.
- Добавлена информация о браузерном расширении RouterForge Portal с переходом к проекту и магазину Chrome.
- Добавлены компактные закрываемые объявления и информация о доступности Stable-канала для MIPS/MIPSEL.
- В каталог добавлены предварительные интеграции opffk и qWDTT Server Keenetic.
- Добавлено одноразовое закрываемое объявление о RouterForge Server; решение пользователя скрыть его сохраняется в браузере.
- В разделе официальных приложений добавлена информационная карточка **RouterForge Server — «В разработке»**, а также страница `/server-hub`.

### Исправления и надёжность

- Для операций обновления Entware результат проверяется по реально установленной версии, а не только по коду завершения процесса.
- Усилены предварительные проверки зависимостей перед удалением пакетов.
- Уточнено отображение версий, установленных компонентов и доступности обновлений.
- Доработаны запросы состояния и защиты от устаревших ответов при переключении страниц, повторной загрузке и изменении авторизации.
- Улучшено поведение настроек при ограничениях браузерного хранилища.
- Обновлён общий дизайн и навигация, расширена локализация RU/EN.

## 2. DNS — штатные резолверы

- Добавлено отображение покрытия DNS Router Gate в интерфейсе основного DNS-модуля.
- Улучшено отображение статусов и согласованность между штатным DNS и отдельным DNS Router.
- Расширены переводы RU/EN и унифицированы элементы интерфейса.
- Существующие возможности управления резолверами, DoT/DoH и состояниями сохранены.

## 3. Admin — syslog-ng, SMB/NAS и восстановление

### Новое управление журналами

- Добавлен интерфейс управления Entware syslog-ng.
- Реализованы просмотр текущего состояния, конфигурации и подключённых источников журналов.
- Добавлены мастер начальной настройки, выбор размещения журналов и раздельная организация записей по устройствам.
- Поддержана работа с USB-накопителями и сетевыми папками SMB/NAS.
- Добавлены просмотр и экспорт журналов, пояснения ошибок подключения и состояния автозапуска.

### Надёжность хранения

- Улучшено восстановление подключения к SMB/NAS после временных сетевых проблем.
- Добавлено различение состояний «ресурс подключён» и «запись журналов доступна».
- Восстановление учитывает работающий syslog-ng и не должно без необходимости прерывать запись журналов.

### Резервное копирование

- Улучшено восстановление конфигураций, размер которых превышает ограничения Config Vault.
- Перед подтверждённым восстановлением сохраняется резервная копия текущей конфигурации.
- Локальные параметры SMB-подключения сохраняются при восстановлении переносимого архива.
- Из резервных копий исключены чувствительные SMB-учётные данные.
- Переработаны административные экраны в рамках перехода на Svelte 5.

## 4. Monitoring — Storage Doctor и SMART

### Новые возможности

- Добавлен Storage Doctor для диагностики физических USB-накопителей, HDD и SSD.
- Отображаются температура и доступная диагностическая информация по накопителям.
- Добавлены признаки и история ошибок USB, операций ввода-вывода и файловой системы.
- Реализован запуск SMART-проверки по явному запросу пользователя.
- Добавлено действие установки `smartmontools` при необходимости.

### Исправления

- Параметры SMART-драйвера сохраняются для конкретного накопителя, а не глобально.
- Кэш SMART и история температур привязываются к идентичности диска.
- При замене USB-накопителя предотвращено отображение устаревших значений и ложных температурных предупреждений.
- Улучшена обработка накопителей без надёжного аппаратного идентификатора.
- Доработано отображение ошибок, статусов сохранения и технических деталей после обновления данных.
- Расширена локализация RU/EN.

## 5. Network Tools

## 6. NFQWS Manager

## 10. DNS Router — новый модуль Stable

DNS Router — самое крупное функциональное добавление после Stable 0.14.0. Он создавался отдельными этапами, проходил через несколько бета-версий и существенно расширился по сравнению с первой доступной сборкой.

### Независимый DNS-сервис

- Добавлен самостоятельный DNS-сервис на основе AdGuard DNSProxy.
- Поддерживаются DNS-запросы UDP и TCP, а также исходящие подключения DoT, DoH и DoQ.
- Предусмотрены основной DNS-сервер, резервные варианты и явные правила fallback.
- Добавлены проверка доступности upstream, сведения о TLS и диагностические данные о задержках.
- Настройки сохраняются отдельно от применения; действующая конфигурация не подменяется несохранённым черновиком.

### Маршрутизация по доменам и спискам

- Добавлены независимые именованные списки доменов с привязкой к DNS-серверам.
- Один DNS-сервер может обслуживать несколько разных списков.
- Предусмотрены правила точного совпадения и доменных суффиксов.
- Поддержаны управляемые HTTPS-подписки доменных списков.
- Редактирование upstream сохраняет его идентификатор и существующие привязки, если изменяется только точка подключения.
- Переработан интерфейс списков и привязок, чтобы работа с одним списком не переписывала соседние.

### Устройства и правила

- Добавлены группы устройств с собственными DNS-настройками и доменными правилами.
- Предусмотрено разделение поведения для разных клиентов локальной сети.
- Доработано отображение выбора устройств, групп и применённых правил.
- Реализовано разделение конфигураций и кэша там, где это предусмотрено выбранным режимом.

### DNS Gate и жизненный цикл

- Добавлен управляемый DNS Gate для обычных UDP/TCP-запросов клиентов LAN.
- Включение перехвата выполняется только явным действием пользователя; установка пакета не активирует его автоматически.
- Добавлены проверки актуального состояния собственных правил NAT/ipset, конфликтов и готовности DNS-сервиса.
- Улучшено сохранение намерения пользователя при перезапуске Entware и обновлении пакета.
- Доработано восстановление перехвата после холодного старта и восстановления firewall.
- Добавлены контроль попыток восстановления, безопасное отключение и диагностика конфликтов.
- Штатный DNS Keenetic и чужие правила firewall не должны изменяться произвольно.

### Локальный DNS и расширенные настройки

- Добавлены локальные записи **A, AAAA, CNAME и PTR** для собственной зоны.
- Расширены настройки TTL, кэша и его разделения по правилам устройств.
- Добавлена поддержка DNS Stamp для совместимых типов защищённых DNS.
- Реализованы настраиваемые входящие DoT, DoH и DoQ с обязательной аутентификацией клиентскими сертификатами mTLS.
- Добавлены расширенные варианты работы с DNS-ответами и диагностика применённых режимов.

### Интеллектуальная обработка IP

- Добавлена работа с ответами A/AAAA, содержащими несколько адресов.
- Реализованы варианты порядка выбора IP, в том числе Round-Robin, случайный выбор и режимы с учётом доступности адресов.
- Добавлены проверки доступности IP, задержек и восстановления после ошибок.
- Дополнительные стратегии включаются пользователем, не изменяя поведение обычного режима автоматически.

### Защита и диагностика

- Добавлены ограничение частоты DNS-запросов и настраиваемая обработка запросов ANY.
- Добавлена обработка ответов, содержащих указанные нежелательные IP-адреса.
- Журнал запросов показывает клиента, домен, тип записи, выбранный DNS-сервер, фактический upstream, ответ и задержку.
- Улучшено объяснение отказов, срабатывания правил, кэша и причин выбора сервера.
- Добавлены данные о доступности upstream и измерениях RTT/p95.
- Переработаны простой и расширенный режимы управления; интерфейс переведён на Svelte 5.

# Часть III. Что важно знать о выпуске

**Все 11 пакетов RouterForge Stable 1.0.0 действительно имеют версию `1.0.0`.** Это подтверждается именами и метаданными IPK, релизными индексами и контрольными суммами. В последующих выпусках независимое версионирование модулей сохраняется.

**DNS Router и основной DNS — разные модули.** Установка DNS Router сама по себе не включает DNS Gate и не заменяет штатный DNS Keenetic. Дополнительные функции, требующие сетевых или сертификатных настроек, применяются только по явному действию.

**RouterForge Server пока представлен информационно.** Отдельный Linux-проект существует, но автоматическая привязка серверов, удалённый мониторинг и управление через RouterForge ещё не реализованы.

**RouterForge Portal — расширение браузера.** Это не Entware-пакет для установки на Keenetic.

**Старые выпуски сохраняются.** При подготовке и публикации финального релиза нужно сохранить прежние Stable и Beta, включая их неизменяемые архивы.
