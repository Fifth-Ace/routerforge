# E04 — explicit native saved-list bindings

Persistent mappings of saved domain groups to dedicated existing native targets (`dns.rf-binding-<id>` or `nfqws.rf-binding-<name>.list`). DNS requires a local paste/file list without auto-update; NFQWS requires a non-protected sorted lowercase plain domain list with LF final newline, no comments or duplicates. Both must be nonempty. No default/auto/IP lists, URL sources, arbitrary files, or background writes. Create dedicated targets in the existing module editor first.

In Policy Objects → Persistent list bindings, refresh, select a saved domain group, enter exact target, preview and confirm attachment (metadata only). Inspect and sync shows additions/removals. Manual target changes block sync/rollback until explicit rebase (discards previous checkpoint). Catalogue save rejects deleting bound groups or using any bound destination as a source in a bound group, including nested references.

Explicit commit checks native-module root-session policy, origin, confirmation, catalogue ETag, registry generation, exact native fingerprint and pinned source projection. DNS calls native local-only `/v1/lists/preview`, rejects unrelated configuration changes, then `/v1/config` PUT with full If-Match. NFQWS calls native `/v1/list/save` with expected SHA256. Inherits existing native CAS guarantees; external filesystem writers must be avoided, not covered by a cross-process lock. No service start/restart/reload, NAT, firewall or startup changes. NFQWS may consume file changes without reload; the UI warns on save. DNS activation remains separate.

Before native save persist before/after hashes and membership; after exact readback checkpoint the result. Ambiguity leaves a pending journal, no automatic retry/rollback. Reconcile only after the original request has finished: inspect whether before/after is observed; unknown state requires manual intervention. Detach removes binding metadata and recovery journal without modifying target. Rollback uses native CAS and previous membership; DNS IDs/timestamps may be regenerated, not byte-exact config restore. NFQWS canonical list rollback restores exact bytes. Native changes after readback are detected on the next inspection.

`/opt/etc/routerforge/policy-bindings-v1.json` created only after explicit attachment, max 16 bindings, 4096 domains/snapshot, 2 MiB file; atomic replacement with file+directory fsync. Corruption fails closed (including catalogue edits). Checkpoints contain selected domain membership, not full module configs, credentials or URLs. One prior checkpoint. No portable catalogue schema changes, no new dependencies. Events contain codes, not paths/content. No runtime-applied claim: activation, real traffic, hardware rollback and full Wave I acceptance remain open.
